# 标签扁平化，不引入维度

Status: accepted（2026-11-17）

## 决策

会话标签只有「名字 + 颜色」这一层：一条会话可挂多个，标签之间没有维度、没有「每个维度只能选一个」的规则。预设的「业务 / 类型」只是可分享的标签包（一包标签的模板），不是结构。

## 背景

最初的方案把标签组织成维度（进度、类型、业务），每个维度每会话单选，进度维度由原生状态派生。实际使用中，用户的工作跨项目、跨目录，一条会话常常同时属于多摊事；维度带来的单选约束和分组 UI 反而增加了整理负担。同时，「进行中 / 待你 / 交回未读」已经由 DSH 原生状态圆点覆盖，再做一个进度维度是重复造指示器。

## 考虑过的替代方案

- **维度化标签（每维单选）**：能自动分组总览，但要求每条会话在每维做一次选择，且总览会被拆成「业务栏 / 状态栏」，与用户「简洁直观」的目标相悖。已否决。
- **单一「业务线」字段 + 自由标签**：仍强制一个主归属，跨项目会话要二选一。已否决。
- **复用 workspace 分组代替标签**：workspace 是目录边界，不等于业务归属；跨项目的事无法表达。已否决。

## 后果

- 侧栏与标题旁只能按数量收纳（`+N`），不能按维度取舍；视觉分组完全交给颜色。
- 标签的语义靠命名习惯和标签包约定，插件不做校验。
- 标签包导入只能按名字合并，冲突时保留本地并报告。
- 若将来重新引入维度，需要一次数据迁移（为标签补维度字段、为会话补每维选择），不能靠改 UI 完成。
